# Hero Sheet Phase 2: honest verdicts, enrichment, skill tree page

**Spec:** `docs/2026-11-16-hero-sheet-design.md`, amended by the "Decisions after the first real scan" section below. Where they disagree, this file wins.

## Decisions after the first real scan

The owner looked at three mockups on real data (211 cards) and chose direction A, "Grimoire" (`git show mockups:mockups/a.html`). Three things were wrong with all of them.

1. **"Dead weight" blamed the item.** An unused skill is usually unused because the agent never reached for it, not because it is useless. The verdict set becomes:
   - `active` (3 or more uses in 30 days), `rare` (1 or 2), `disabled`, `unknown` (no usage signal for this kind)
   - `asleep`: 0 uses and no evidence it was ever relevant. Neutral, not an error.
   - `missed`: 0 uses, but a skill oracle recommended it at least once in a session that then did not load it. This is the agent's failure and the number that matters.
   Every card also carries `usage.missed30d`, including active ones.
2. **Too much at once.** A flat grid of 151 cards is not a character sheet. The default view is a skill tree: branches by domain, packs inside a branch, nodes inside a pack. Details open on click.
3. **Red first.** The default view shows what works. Nothing is sorted or filtered toward failures by default; asleep nodes are dim, not alarming. Missed nodes carry a small marker.

The page is bilingual, English and Russian, with a switch in the header. English is the default; the choice is remembered in `localStorage`.

Later phases, recorded so the data layer does not block them: a scheduled self-check that replays recent sessions against the rules and reports how well the agent followed its harness; tools on the page to run those checks on demand.

## Shared contract (both work packages build against this)

Added to `src/types.ts`:

```ts
export type Verdict = 'active' | 'rare' | 'asleep' | 'missed' | 'disabled' | 'unknown';
export interface Usage { uses30d: number; lastUsedAt?: string; lifetimeUses?: number;
  outTokens?: number; ctxGrowth?: number; missed30d?: number; }
export type BranchId = 'code' | 'design' | 'research' | 'writing' | 'data' | 'automation'
  | 'memory' | 'communication' | 'finance' | 'system' | 'other';
export interface Localized { en: string; ru?: string; }
export interface Card /* extends Item, as before */ {
  branch: BranchId;        // always set; 'other' or a kind-based default when not enriched
  pack: string;            // grouping inside a branch: owning plugin name, 'user', 'desktop', 'synced', 'connectors', 'app'
  title?: Localized;       // short display name
  summary?: Localized;     // one or two plain sentences: what it does and when it is used
  art?: string;            // optional image URL or data URI; absent until an image step exists
}
export interface State { /* as before, plus: */ enriched: boolean; sessions: number; }
```

Default branch when not enriched: `mcp_server` and connectors go to `system`, `memory` and `instructions` to `memory`, `hook` and `scheduled_task` to `automation`, everything else to `other`.

## Work package A: scanner changes and enrichment (branch `phase2-tree`, main checkout)

1. **Verdicts.** Rename `dead_weight` to `asleep` everywhere (types, join, tests, journal, README). Add `missed`.
2. **Missed detection.** New `src/usage/oracle.ts`: `missedFromTranscripts(roots, oracle, sinceDays, now?) => Promise<Map<string, number>>` keyed by skill ref. An oracle is configured in the rules file as `{ "oracle": { "command": "^jev-skill ", "line": "^- (?<skill>\\S+) \\(fit (?<fit>[0-9.]+)\\)", "minFit": 0.5 } }` next to `rules`. For each session: find Bash tool calls whose command matches `command`, read the matching tool result text, collect skills whose fit is at least `minFit`; any of them not loaded through the Skill tool later in that same session counts once per session. No oracle configured means no `missed` verdicts. The rules file becomes an object `{ rules: [...], oracle?: {...} }`; a bare array is still accepted.
3. **Branch and pack.** `buildCards` sets `branch` to the default above and `pack` from origin and surface.
4. **Enrichment.** New command `hero-sheet enrich [--cmd "<shell command>"] [--batch 25]`.
   - Reads `state.json`, sends cards without a cache hit to the describer in batches, writes results into a cache file `<stateDir>/enrich.json`, then rewrites `state.json` with `branch`, `title`, `summary` applied and `enriched: true`. `scan` applies the cache too, so a rescan keeps descriptions.
   - Cache key: sha256 of `kind`, `name`, `description`. Unchanged items are never sent again.
   - Describer protocol: the command receives one JSON object on stdin, `{ branches: BranchId[], items: [{ id, kind, name, description, sampleTools? }] }`, and prints one JSON array `[{ id, branch, title: {en, ru}, summary: {en, ru} }]`. Anything else on stdout around the JSON is tolerated (take the outermost array). Invalid entries are skipped with a warning; an unknown branch becomes `other`.
   - Default command: `claude -p --model haiku` with the instruction text shipped in `src/enrich/prompt.ts`. The prompt asks for a title of at most four words and a summary of at most 30 words per language, written for a person who has never opened the skill file, with no marketing words.
   - Only `id`, `kind`, `name`, `description` and connector `sampleTools` are sent. Paths and config values are not.
   - Tests use a stub describer command (a small node script in `test/fixtures`), never a real model.
5. **`sessions`** in state comes from the usage source.

## Work package B: the page (branch `phase2-page`, separate worktree)

`hero-sheet serve [--port 4477] [--state <file>]` serves a static page from `web/` plus the state file at `/state.json`. No build step: plain ES modules, hand-written CSS, no framework, no external requests. `web/sample-state.json` is synthetic and is used when no state exists.

Visual direction: A, "Grimoire". Reuse its palette, type and emblem generator; redesign the layout around a tree. Load and follow the `impeccable` design skill for this work.

- **Hero header:** name, level, class, four totals (items, active, asleep, missed), language switch. Level and class stay the simple derivation from the mockup for now.
- **Tree (default view):** one region per branch that has items, branch title and a count of lit nodes out of total. Inside it, packs as labelled clusters; inside a pack, nodes. A node is an emblem with the title under it. States: lit (active), half-lit (rare), dim (asleep), dim with a marker (missed), locked (disabled), plain (unknown). State must be readable without colour.
- **Node detail:** clicking a node opens a panel or card with title, summary, kind, surface, pack, uses in 30 days, lifetime uses, missed count, context cost estimates labelled as estimates, version and update flag, and the raw description behind a disclosure.
- **Surface switch:** all, Code and CLI, account-synced, desktop app, connectors. Default is all.
- **Quests panel:** rule results with progress toward target.
- **Search** by name across the tree.
- **Language:** every UI string comes from a dictionary with `en` and `ru`. Card text uses `title` and `summary` in the chosen language, falling back to English, then to `name` and `description`.
- **Empty and partial data:** a state that is not enriched still renders (default branches, raw names). A branch with one item still looks intentional.
- Works at phone width and desktop width, light and dark.

## Acceptance (reviewer)

- All tests pass, typecheck clean.
- `scan` then `enrich` on a real setup: every card has a branch, cached rerun sends nothing.
- No path, env value or header value in what is sent to the describer.
- The page renders real state in both languages with no console errors.
